# Security Policy

## Supported Versions

We provide security updates for the following versions of this ERP repository:

| Version | Supported |
| ------- | --------- |
| 5.1.x   | :white_check_mark: |
| 5.0.x   | :white_check_mark: |
| 4.0.x   | :x: |
| < 4.0   | :x: |

## Reporting a Vulnerability

Please do not open a public issue or post details of a suspected vulnerability in a public forum.

To report a security issue, email the maintainers at security@your-domain.example with a clear description of the issue, affected version(s), steps to reproduce, and any relevant logs, screenshots, or proof-of-concept code. If email is not possible, contact the project maintainers through the private channel listed in the repository contacts.

We will acknowledge receipt within 2 business days and provide an initial assessment within 5 business days. If the issue is confirmed, we will share a remediation plan and expected timeline as soon as practical.

Please keep the report confidential until we have had a chance to investigate and coordinate a fix. We will work with you to validate the issue, determine impact, and prepare a patch. After the fix is available, we will coordinate disclosure timing with the reporter when possible.

## Disclosure Expectations

We aim to handle security reports responsibly and transparently:

- Confirmed vulnerabilities are addressed privately before public disclosure.
- We may request additional information or a retest to verify the fix.
- Once a fix is released, public disclosure should wait until an agreed date or until we confirm that the patch is available.
- If a report is not accepted as a vulnerability, we will explain the reasoning and close the report privately.

Thank you for helping us keep this ERP project secure.
